# d9-plumbing

`d9-plumbing` is the CLI shipped with `@wbce/projen-d9`. It saves the state of a d9 instance (schema, configuration data, files, permissions) into the repository and applies it to another instance.

Run it from the root of the d9 project, either directly or through the generated projen task:

```sh
npx d9-plumbing <command> [options]
npx projen d9-plumbing <command> [options]
npx d9-plumbing --help              # list commands
npx d9-plumbing <command> --help    # list the options of a command
```

It works with the following files of the project:

| Path | Content |
| --- | --- |
| `sql/schema.sql` | Database schema, dumped with Atlas |
| `sql/data/*.csv` | Content of the d9 configuration tables |
| `sql/tables_to_dump.txt` | Optional, extra tables to dump (one per line) |
| `sql/tables_not_to_dump.txt` | Optional, tables never to dump (one per line) |
| `permissions/<Role>/*.cedar` | Permissions as Cedar policies, generated from `sql/data/directus_permissions.csv` |
| `d9-plumbing.json` | CLI configuration, generated by projen |

## Configuration

The d9 environment (`.env`, environment variables) is read through `@wbce-d9/api`, resolved from the d9 project, so the CLI uses the same configuration as d9 itself.

### Database

| Flag | Fallback |
| --- | --- |
| `--host <host>` | `DB_HOST` |
| `--user <user>` | `DB_USER` |
| `--password <password>` | `DB_PASSWORD` |
| `--database <database>` | `DB_DATABASE` |
| `--ssl` | `DB_SSL`, or any nested `DB_SSL__*` key (Directus syntax, e.g. `DB_SSL__REJECT_UNAUTHORIZED`) |

### Current storage

The storage of the d9 instance: the first location of `STORAGE_LOCATIONS`, configured by `STORAGE_<LOCATION>_*`. Each entry can be overridden with the repeatable `--storage-config key=value` flag (nested keys use dots, e.g. `--storage-config driver=s3 --storage-config bucket=my-bucket`).

### Intermediate storage

A storage shared between environments, used to transfer the files referenced by `sql/data/directus_files.csv`. It is resolved from, by increasing priority:

1. `intermediateStorage` in `d9-plumbing.json` (`driver`, `options`, and `secretEnv` which maps an option to the name of the environment variable holding its value). Set it with `project.configurePlumbing({ intermediateStorage })` in `.projenrc`.
2. `INTERMEDIATE_STORAGE_*` environment variables (e.g. `INTERMEDIATE_STORAGE_DRIVER=s3`).
3. The repeatable `--intermediate-storage-config key=value` flag.

### Logging

The log level is `LOG_LEVEL`, else `logLevel` in `d9-plumbing.json` (`project.configurePlumbing({ logLevel })`), else `debug`.

### Atlas

The schema is dumped and diffed with [Atlas](https://atlasgo.io/) Community Edition. The binary is downloaded from release.ariga.io on first use and cached in `node_modules/.cache/d9-plumbing`. Its version is set by `packageVersions.atlas`.

## Commands

### `save`

Saves the current d9 into the repository, then pushes its files to the intermediate storage.

1. Dumps the schema into `sql/schema.sql`.
2. Empties `sql/data` and dumps one CSV per table: every `directus_*` table except `directus_users`, `directus_sessions`, `directus_revisions`, `directus_activity` and `directus_presets`, plus the tables of `sql/tables_to_dump.txt`, minus those of `sql/tables_not_to_dump.txt`. Columns referencing a user are replaced by a fixed CI user. `directus_files` and `directus_folders` are limited to the `common` folder and its subfolders.
3. Regenerates the Cedar policies in `permissions/` (see [`d9-to-cedar`](#d9-to-cedar)).
4. Pushes the files to the intermediate storage (see [`push-files`](#push-files--pull-files)).

Options: [database](#database), [storage](#current-storage), [intermediate storage](#intermediate-storage), `--no-cedar` to skip step 3.

```sh
npx d9-plumbing save
```

### `apply-schema`

Applies the saved state of the repository to the current d9.

1. Checks that the current d9 has no unsaved changes (see [`check-unsaved`](#check-unsaved)).
2. Pulls the files from the intermediate storage.
3. Applies the SQL snapshot and imports the reference tables.

Once done, purge the d9 cache (`POST /utils/cache/clear`) so the new schema, and permissions when `CACHE_ENABLED` is set, are taken into account. Restart d9 if flows, operations or webhooks changed.

Options: [database](#database), [storage](#current-storage), [intermediate storage](#intermediate-storage), and:

| Option | Description |
| --- | --- |
| `--last-save <commit>` | Commit of the last save of this environment, required |
| `--no-last-save` | Skip the unsaved changes check (asks for confirmation) |
| `--yes` | Do not ask for confirmation |

```sh
npx d9-plumbing apply-schema --last-save 1b3387a
```

### `first-import`

Initializes an empty d9 database: applies the snapshot, then pulls the files if an intermediate storage is configured. Does nothing if the database already contains `directus_*` tables. Called by the `first-run` task (`npx projen first-run`).

Options: [database](#database), [storage](#current-storage), [intermediate storage](#intermediate-storage).

```sh
npx d9-plumbing first-import --host localhost --user d9 --password d9 --database d9
```

### `check-unsaved`

Fails if the current d9 differs from the state saved at `--last-save`. It compares the result of a fresh save with the `sql/` folder of the `--last-save` commit. Run by `apply-schema` before applying anything.

Options: [database](#database), `--last-save <commit>`, `--no-last-save`, `--yes` (see [`apply-schema`](#apply-schema)).

```sh
npx d9-plumbing check-unsaved --last-save 1b3387a
```

### `push-files` / `pull-files`

Syncs the files listed in `sql/data/directus_files.csv` from the current storage to the intermediate storage (`push-files`), or the other way (`pull-files`). Run by `save` and `apply-schema`.

Only the files of the d9 folder named `common` and its subfolders are saved and transferred: `save` dumps only those rows of `directus_files` and `directus_folders`, so everything else stays local to its environment. Put the files shared by all environments (logos, default images...) in `common`.

Options: [storage](#current-storage), [intermediate storage](#intermediate-storage).

```sh
npx d9-plumbing push-files
```

### `d9-to-cedar`

Deletes the permissions folder and regenerates it from `directus_permissions.csv` and `directus_roles.csv`. Each role gets a folder with:

- `authorize.cedar` — which actions the role can do on which collections, with their filters,
- `check-fields.cedar` — the fields allowed per action,
- `validate.cedar` — the validation rules.

Policies sharing the same conditions are grouped into a single `action in [...]` policy. Permissions without a role are in the `Public` folder. Run by `save`.

| Option | Default | Description |
| --- | --- | --- |
| `--permissions <path>` | `./permissions` | Cedar policies folder |
| `--sql <path>` | `./sql/data` | CSV folder |

### `cedar-to-d9`

The reverse of `d9-to-cedar`: reads the Cedar policies and merges them into `directus_permissions.csv`. The `permissions`, `fields` and `validation` columns are rewritten; the other columns (`id`, `role`, `presets`) are kept from the existing CSV. A (role, collection, action) added in Cedar creates a row, one removed from Cedar deletes its row. Every role folder must match a role of `directus_roles.csv` (except `Public`).

| Option | Default | Description |
| --- | --- | --- |
| `--permissions <path>` | `./permissions` | Cedar policies folder |
| `--sql <path>` | `./sql/data` | CSV folder |
| `--output <path>` | `<sql>/directus_permissions.csv` | Output CSV |

### `sync`

Not implemented yet.

## Workflows

### Promote changes to another environment

1. Make the changes in d9 on the source environment (usually local).
2. `npx d9-plumbing save`, commit `sql/` and `permissions/`, merge.
3. On the target environment, from the merged commit: `npx d9-plumbing apply-schema --last-save <commit of the last save of the target>`. If the target has changes that were never saved, the command fails: run `save` there first, commit and merge, then retry.
4. Purge the d9 cache of the target.

### Modify a permission with Cedar

1. Edit the policies in `permissions/<Role>/*.cedar`.
2. Write them back into the CSV:

   ```sh
   npx d9-plumbing cedar-to-d9
   ```

3. Review the result with `git diff sql/data/directus_permissions.csv`.
4. Apply it to the local d9. The local database has not changed since the last commit, so use `HEAD` as the last save:

   ```sh
   npx d9-plumbing apply-schema --last-save HEAD
   ```

5. Purge the d9 cache and check the permissions in d9.
6. Optionally run `npx d9-plumbing d9-to-cedar` to normalize the Cedar files (grouping, ordering) as the next `save` will.
7. Commit the `.cedar` files and the CSV together, then promote them as above.
